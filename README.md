# 응용 - 스프링부트+리액트 웹앱


1. 프로젝트 설정
	1. 프레임워크는 스프링 부트 사용
	2. 최종적으로 단일 웹앱, 단일 포트 사용 상정
		1. 개발상태에서
			1. localhost - 스프링 부트 웹앱 서버(:8080)와 리액트 서버(:3000) 별도로 실행
			2. 웹앱 서버에 접속하면 리액트 서버의 index.html로 포워딩
			3. 이후 웹앱 서버는 api서버로만 동작
			4. 클라이언트 요청시 :3000(리액트) -> 웹앱서버로 proxy
				1. 리액트 앱의 package.json 에 
				   "proxy" : "http://localhost:8080" 추가 
					1. => 리액트에서 라우팅되지 않는 모든 요청 경로를 해당 주소로 프록시함
					2. 상대경로로 작성한 요청에만 적용됨

		2. 배포할때
			1. 개발환경에서 해둔 리액트의 프록시(package.json) 설정 제거, 
			   백엔드에서 "/" 경로 요청을 리액트 서버 포트 주소로 리다이렉트 하던 설정은 "forward:/index.html" 를 리턴하도록 변경
			2. 리액트 프로젝트 빌드. (npm run build) 
			3. 빌드 결과물들을 스프링 부트 프로젝트의 src/main/resources/static/ 경로에 배치. 이후 백엔드 서버는 컨트롤러에서 리턴하는 경로를 static 경로에서 찾아 정적 리소스 반환. 
			   return "forward:index.html" => 클라이언트가 정적 리소스 index.html 을 전달받음.
			4. 마지막으로 부트 프로젝트 빌드(mvn clean package) 해서 jar 파일 생성
			5. java -jar <jar파일명> 으로 해당 웹앱 실행
